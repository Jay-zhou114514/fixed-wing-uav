# 项目规范（迁移自 motor-health-monitor）

本文件是新项目「固定翼无人机风扰下航迹可执行性」的规则集，逐条对应
第一个项目 `motor-health-monitor` 已经跑通的那一套。

## 0. 迁移原则

第一个项目的价值不在「轴承检测」这个方法本身，而在于它把一次本科项目
变成了一条**可追溯的证据链**：每个数字都能追到脚本 + 日志 + CSV + 图，
每条结论都标了证据等级，每次路线变化都留了记录。

要复制的是这条证据链的机制，不是它的题目。

## 1. 逐条迁移表

| # | motor-health-monitor 的做法 | 它当初解决的问题 | 本项目对应做法 |
| --- | --- | --- | --- |
| 1 | Master 仓库是唯一事实来源，论文层只做「抽取 + 组织」 | 数据分叉、两份结果不一致 | 本仓库是 Master。作品集/论文材料只引用，不复制数据 |
| 2 | 固定工作流：实验完成 → 结果审查 → 假说判定 → 风险审查 → 更新路线 → 发版 | 边跑边改题、结论跟着计划走 | 同一流程，见第 3 节 |
| 3 | 实验编号 `EXP-V1-0X`，永不复用、永不重排 | 引用混乱、无法追溯 | 改用 `EXP-FW-V1-0X`（FW = fixed wing），规则相同 |
| 4 | 一个实验 = 契约 + 脚本 + 日志 + CSV + 图 + 记录 | 结果无法复现 | 同上，见第 4 节 |
| 5 | 契约在跑之前写定：Hypothesis / Data / Train / Test / Method / Metrics / Rule | 事后凑判据 | 预注册文件必须在产生任何结果前写并提交 |
| 6 | 阈值、协方差、超参数只由训练/验证数据确定，测试集只开一次 | 数据泄漏导致虚高 | 场景集 train/val/test 分离，见第 7 节 |
| 7 | 证据等级 A/B/C/D，C/D 不得进摘要与结论 | 过度解读 | 原样保留，见第 5 节 |
| 8 | 三层次报告 Observation / Interpretation / Limitation | 把解释写成观察 | 原样保留，写进每份实验记录 |
| 9 | CHANGELOG 只写触发条件，不预写版本内容 | 计划绑架研究 | 原样保留，见第 6 节 |
| 10 | 新版本必须回答六个问题 | 版本更新变成流水账 | 原样保留，模板见 `docs/plans/VERSION_UPDATE_TEMPLATE.md` |
| 11 | 失败实验保留，负结果是结果 | 只报好消息 | 原样保留 |
| 12 | 每个数字都要能追到实验编号 + 脚本 + CSV；论文只引用已冻结结果 | 幻觉证据 | 原样保留，另见 `docs/DECISIONS.md` FW-D-003 |
| 13 | 桌面导出用「中文名 + 版本号」 | 文件难认 | 原样保留，见第 9 节 |
| 14 | 不整包安装 skill；新 skill 必须有可区分的 name/description 与实质内容 | 路由被稀释 | 若要为本项目建 skill，沿用同一门槛 |

## 2. 哪些 Motor 概念在新项目里要换名字

| Motor 概念 | 本项目对应 |
| --- | --- |
| 训练文件 / 测试文件划分 | 训练场景集 / 验证场景集 / 测试场景集划分 |
| 「阈值只能用正常数据确定」 | 「规划参数、安全裕度、判据只能用 train/val 场景确定」 |
| 跨数据集验证（MFPT → NASA IMS） | 跨环境族验证（不同障碍密度 / 风场族），外加可选的 6 自由度或 JSBSim 交叉验证 |
| 误报 / 漏报代价 | 不适用；本项目用「假安全（规划认为可行但实际碰撞）」与「过度保守（可行但绕远）」替代这组代价 |
| 特征工程 | 几何表示与代价函数设计 |

## 3. 固定工作流

```text
实验完成 → 结果审查 → 假说判定 → 风险审查 → 更新研究路线 → 发布新版本
```

任何一步都不能跳过。没有结果审查就不做假说判定，没有风险审查就不改路线。

风险审查五问（沿用，逐条换成新项目的说法）：

1. 场景数量与统计功效够不够？
2. 样本独立性：同一场景族、同一随机种子的重复算不算独立？
3. 多重比较：扫了 132 个 (w, θ) 组合有没有校正？
4. 事后观察与预先定义假设的区分。
5. 泛化风险：只有本仿真、只有常值风、只有 3 自由度模型。

## 4. 每个实验必须交付的东西

1. 预注册契约（跑之前）
2. 脚本
3. 运行日志（含随机种子与参数）
4. 结果 CSV
5. 图
6. 实验记录（Observation / Interpretation / Limitation 三层分开）

缺任何一项，实验状态就是「部分完成」，不得作为正式结论引用。

## 5. 证据等级

| 等级 | 含义 |
| --- | --- |
| A | 在本仿真中已被受控实验证实 |
| B | 与现有证据一致，需进一步确认 |
| C | 尚未成立（置信区间重叠、无法排除随机波动） |
| D | 未知（跨模型、跨环境族、真实飞行） |

等级 C/D 的内容不得写入摘要或结论。

## 6. 计划版本必须回答的六个问题

1. 已确认事实（有实验支持、标了等级）
2. 被否定或弱化的假设
3. 当前最可信机制（最多 3 条，各标等级）
4. 当前最大科研风险
5. 下一实验及理由
6. 论文/作品集故事如何随证据变化

## 7. 从 Motor 踩过的坑直接继承的三条硬约束

这三条是花过代价换来的，本项目开局就执行。

1. **功效优先。** Motor 的 V1.4 功效分析发现：22 个训练窗口、11 个正常测试窗口下，
   关键假设的统计功效只有 0.087 与 0.180，导致一个阴性结果只能表述为「功效不足、无法判定」，
   不能表述为「未复现」。本项目在 EXP-FW-V1-03 之前必须先做场景数量的功效估算，
   否则同样会卡在「说不清」。
2. **独立性要事先想清。** Motor 的 50% 重叠窗口不是独立样本，这件事一直在限制结论强度。
   本项目对应的问题是：同一随机种子、同一风场样本的多次重复、以及同一障碍族内的相关场景。
   这些问题必须在预注册时写清楚处理方式。
3. **测试集只开一次。** Motor 早期在测试集上选过最优阈值（事后最优），后来专门补了
   泄漏安全的 leave-one-file-out 版本。本项目对应的是测试场景集：一旦用来比较方法，
   就必须记为 post-hoc。

## 8. 命名

- 实验：`EXP-FW-V1-0X`，记录 `EXP-FW-V1-0X-<短名>.md`，结果 `EXP-FW-V1-0X-<短名>.csv`
- 计划：`docs/plans/RESEARCH_PLAN_v<major>.<minor>.md`
- 结构性决策：`docs/DECISIONS.md` 中 `FW-D-00X`
- 桌面导出：中文名 + 版本号，例如 `固定翼研究计划_V1.0.md`

## 9. 与本项目 skill 的关系

Motor 建了项目专用 skill `motor-health-monitor-research` 来固化约定。
本项目在规范稳定（至少跑完 EXP-FW-V1-03）之后再建对应的 skill，
门槛沿用 Motor 的 D-004：必须有可区分的 name/description 与实质内容，
且要通过官方校验器。
